# ADR-005: GoでZ-score事前フィルタリング後にPythonを呼び出す

**ステータス**: 承認済み  
**日付**: 2026-07-05

## コンテキスト

毎分・全監視銘柄の価格を取得するが、Pythonへの呼び出し（テクニカル分析 + 外部API）はコストが高い。すべての銘柄を毎分Pythonへ送信すると、ユーザー×銘柄数が増加したときに負荷が線形に増大する。

## 決定

GoがRedisにキャッシュした直近30件の終値から平均・標準偏差を計算し、現在値のZ-scoreが **閾値（デフォルト2.5σ）** を超えた場合のみPythonへ送信する。閾値はユーザーが銘柄ごとに変更可能（`watchlist.alert_threshold`）。

## 理由

- Z-scoreの計算はGoで完結（Redisから30件取得 → 計算）し、追加インフラ不要
- Pythonへのリクエストを大幅に削減し、外部API（Finnhub・Claude）のコストも抑制
- 「GoとPythonで責務を分担する」という設計方針と一致（GoはI/O処理・軽量スクリーニング、Pythonは高精度分析）

## デフォルト閾値の根拠

- 2.5σ: 統計的に約1.2%の事象。通常の価格変動ノイズを除外しつつ、重要な異常を捉えられるバランス点。
- 2.0σだと通知過多のリスク、3.0σだと重要な動きを見逃す可能性がある。
